Alunos: Eduardo da Rocha Ventura, João Pedro de Medeiros Costa e Thiago Luis da Silva Costa


**Relatório GitHub no Robocode**

**1. Introdução**

Robocode é um simulador onde você programa robôs para lutar automaticamente em uma arena. Ele é usado para aprender e praticar conceitos de programação. O objetivo dessa atividade é melhorar nosso trabalho em equipe, ajudar a praticar e melhorar nossos conceitos em programação, e pôr em prática os conceitos abordados em salas sobre controle de versão, onde teremos que usar o Git para desenvolver o nosso robô em cooperação com a nossa equipe, onde é de extrema importância pois o controle de versão permite registrar e gerenciar alterações no código, facilitando a colaboração, a organização do projeto e a recuperação de versões anteriores durante o desenvolvimento de software.


**2. Objetivos da Atividade**

   - Aprender e aplicar conceitos de programação utilizando o Robocode. 
   - Desenvolver estratégias para controlar os robôs durante as batalhas. 
   - Compreender o funcionamento do Git como ferramenta de controle de versão. 
   - Utilizar o GitHub para armazenar e compartilhar o código do projeto. 
   - Praticar o trabalho em equipe por meio da colaboração entre os integrantes do grupo. 
   - Aprender a registrar alterações no código utilizando commits. 
   - Organizar o desenvolvimento do projeto através de branches e controle de versões.


**3. Descrição da Atividade**

O desenvolvimento do tanque no Robocode foi realizado utilizando a linguagem Java. Inicialmente, foram estudadas as funcionalidades básicas do Robocode, como movimentação, detecção de inimigos e disparos. Em seguida, foram implementadas estratégias para melhorar o desempenho do robô durante as batalhas, incluindo movimentação constante para evitar tiros adversários, rastreamento de inimigos através do radar e definição de momentos adequados para atacar. Após cada alteração, foram realizados testes para verificar o comportamento do robô e identificar possíveis melhorias.

_**Como o Git foi utilizado para controle de versão**_

O Git foi utilizado para registrar todas as modificações realizadas durante o desenvolvimento do projeto. Cada integrante realizou alterações em partes específicas do código e registrou essas mudanças por meio de commits. Dessa forma, foi possível acompanhar a evolução do projeto, recuperar versões anteriores quando necessário e evitar a perda de trabalho. O Git também facilitou a integração das contribuições dos membros da equipe.

O GitHub foi utilizado como plataforma para armazenar e compartilhar o repositório do projeto. Cada integrante teve acesso ao código e pôde contribuir de forma organizada. As alterações foram enviadas ao repositório remoto através de push, permitindo que todos acompanhassem o progresso do trabalho. A colaboração foi facilitada pelo uso de branches e pull requests, reduzindo conflitos e tornando o desenvolvimento mais eficiente.


**4. Estrutura do Git Utilizada**

_**Repositório: Como foi criado e organizado**_

Foi criado um repositório no GitHub para armazenar todo o código-fonte do projeto. O repositório foi organizado de forma que os arquivos do Robocode permanecessem centralizados e acessíveis a todos os integrantes. Isso permitiu um melhor gerenciamento do projeto e facilitou o acompanhamento das alterações realizadas.

   - Branches: Diferentes branches criadas e propósito de cada uma
   - Durante o desenvolvimento foram utilizadas diferentes branches para organizar as tarefas:
   - main: branch principal, responsável por armazenar a versão estável e funcional do projeto.
   - develop: utilizada para integrar novas funcionalidades antes de serem enviadas para a main.
   - feature: criada para o desenvolvimento de funcionalidades específicas, como melhorias na movimentação, no sistema de ataque ou no radar do robô.
   - Essa organização permitiu que os integrantes trabalhassem simultaneamente sem interferir diretamente no código principal.
   - Commits: Importância e forma de utilização

Os commits foram utilizados para registrar cada conjunto de alterações realizadas no código. Foram escritas mensagens claras e objetivas para facilitar a identificação das modificações, como “Adiciona movimentação evasiva”, “Corrige erro no radar” ou “Melhora estratégia de ataque”. Essa prática tornou mais simples acompanhar o histórico do projeto e localizar alterações específicas.

_**Pull Requests: O que são e como foram utilizados**_

Os pull requests foram utilizados para solicitar a integração de alterações desenvolvidas em branches secundárias para as branches principais. Antes da integração, o código era revisado para verificar possíveis erros ou conflitos. Esse processo ajudou a manter a qualidade do projeto e garantiu que as novas funcionalidades fossem incorporadas de forma segura e organizada.


**5. Resultados e Aprendizados**

Durante o tempo de elaboração do nosso robô, tivemos vários episódios em que não conseguíamos entender o motivo do nosso código não funcionar. Foi importante para treinar atenção, revisar o código, fazer ajustes no que era necessário e discutir entre o grupo o que julgamos necessário incluir no código ou não. Nos nossos testes, tivemos bons resultados, os quais não foram visíveis a todos devido ao erro de compilação no dia da batalha. Nosso maior desafio foi fazer um código enxuto mas completo, para que nosso robô não fosse previsível em campo e conseguisse se sobressair perante os outros. Nesse tempo de preparação, desenvolvemos comunicação em grupo, maiores habilidades em programação e também afiamos nosso pensamento lógico. Todas essas habilidades são proveitosas no dia a dia e na nossa rotina como futuros programadores e analistas de sistemas.


**6. Conclusão**

A atividade permitiu consolidar conhecimentos de programação em Java, desenvolvimento de estratégias no Robocode e utilização do Git e GitHub para controle de versão e colaboração. Além do aprimoramento técnico, foi possível desenvolver habilidades de comunicação, organização e resolução de problemas em equipe. Os conhecimentos adquiridos poderão ser aplicados em futuros projetos de software, tornando o desenvolvimento mais eficiente, organizado e colaborativo, características essenciais para a atuação profissional na área de tecnologia.
